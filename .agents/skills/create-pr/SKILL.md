# Pull Requestの作成

既存の `AGENTS.md` に記載された開発・Gitルールを最優先する。Pull Requestを自動マージしない。

## 事前確認

1. `git status`、現在のブランチ、ベースブランチ、差分を確認する。
2. `main` ブランチ上ではコミット、push、Pull Request作成を行わない。`main` から作成した作業ブランチを使用する。
3. 変更内容を確認し、意図しないファイルをコミット対象から除外する。
4. 実行したテストと結果を確認する。テスト実行にはユーザーの事前承認を求めない。テストが失敗した場合は原因を調査し、結果を報告する。

## 承認と実行

コミット、push、Pull Request作成は独立した外部変更である。各操作の直前に、その操作だけを対象とするユーザーの明示的な承認を得る。前の操作が成功した場合だけ次の操作に進む。

1. コミットが必要な場合は、コミット対象、コミットメッセージ、テスト結果を提示して承認を得てから、日本語のコミットメッセージでコミットする。
2. コミットが成功した場合、またはコミット不要で既存の未push対象コミットを確認した場合は、対象ブランチ、pushするコミット、push先を提示して承認を得てから、作業ブランチだけを `origin` へ通常のpushで送信する。`main` への直接pushとforce pushは禁止する。
3. pushが成功した場合は、Pull Requestのベースブランチ、タイトル、本文を提示して承認を得てから、GitHub CLIでPull Requestを作成する。タイトル・本文は日本語とし、`AGENTS.md` のPull Request本文ルールに従う。

作成したPull RequestのURL、実行した操作、テスト結果を報告する。

GitHub CLIが利用できない、認証されていない、または権限が不足する場合は、代替の外部変更を行わず、状況を報告する。
